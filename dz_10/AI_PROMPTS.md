## 1. Code Review (views/serializers)

```
Ты работаешь в моём Django-проекте "Книжковий магазин" (репозиторий уже открыт).

Задача:
1. Найди в проекте 3 самых сложных/нагруженных файла среди views.py и serializers.py
   (по количеству логики, вложенности, кастомных методов) — не самые тривиальные.
2. Для каждого из 3 файлов:
   a. Покажи мне текущий код (оригинал) с указанием пути к файлу.
   b. Проведи code review: производительность (N+1 запросы, select_related/
      prefetch_related), безопасность, дублирование кода, соответствие DRF best
      practices, читаемость, обработку ошибок.
   c. Дай список конкретных рекомендаций с обоснованием (не общие фразы).
3. Реализуй только те рекомендации, которые реально улучшают код и не ломают
   существующее поведение/тесты. Если тестов нет — не ломай текущую бизнес-логику.
4. Сформируй файл AI_REVIEW.md в корне проекта со структурой для КАЖДОГО из 3 файлов:

   ## Файл: <путь>
   ### Оригінальний код
   ```python
   ...
   ```
   ### AI рекомендації
   - ...
   ### Фінальний код (після застосування)
   ```python
   ...
   ```
   ### Що змінено і чому
   - ...

Не удаляй функциональность. Прогони существующие тесты (если есть) после правок
и покажи результат в конце.
```
## 2. Генерация тестов + coverage
```
Задача в этом же проекте:

1. Выбери 2-3 модели (Django models), которые ещё слабо покрыты тестами
   (проверь текущий coverage, если конфиг для coverage.py уже есть; если нет —
   настрой pytest + pytest-cov / coverage.py).
2. Сгенерируй unit-тесты для этих моделей: создание объектов, валидация полей,
   методы модели, свойства (properties), __str__, связи (ForeignKey/M2M),
   edge cases (пустые/невалидные значения).
3. Каждый тестовый метод должен содержать в начале докстринг или комментарий:
   # Generated with AI, reviewed and modified
4. Прогони тесты, убедись что все проходят (0 failures).
5. Посчитай coverage именно для этих моделей (files/modules filter) и убедись,
   что он ≥ 60%. Если ниже — добавь недостающие тест-кейсы.
6. В конце выведи:
   - список созданных тестовых файлов
   - команду для запуска тестов
   - итоговый coverage report (текстом или таблицей) именно по этим моделям
   - сохрани отчёт в файл coverage_report.txt (или html через `coverage html`)
```
